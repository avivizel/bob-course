# Agent Mode Rules

## Never edit generated HTML files directly
All 35 HTML files at the root (`index.html`, `chapter-*.html`) are fully regenerated by `node scripts/build.mjs`. Edit only the `.mjs` data files in `scripts/`, then rebuild.

## Safe HTML insertion
The only place raw (unescaped) HTML is accepted is `ch.deep.html`. All other string fields must be plain text — the `esc()` function in `build.mjs` handles escaping and `«»`→`<strong><em>` conversion.

## Adding a chapter
- Chapters 1–10 go in `scripts/chapters-part1.mjs` (append to `CHAPTERS` array).
- Chapters 11–34 go in `scripts/chapters-part2.mjs` (append to `CHAPTERS_PART2` array).
- Both arrays are merged as `const ALL = [...CHAPTERS, ...CHAPTERS_PART2]` in `build.mjs` — order within each file determines page order.
- If adding a new `phase` id, also update `phaseBadge()` in `build.mjs` with a colour mapping.
- The 7 valid phase ids are: `foundation`, `bob`, `product`, `build`, `ai`, `quality`, `enterprise`.

## Concept popup details
Add per-chapter detail entries to `scripts/concept-details.mjs` using the key `"chapterNum:term"` (e.g., `"15:CSS Grid"`). A bare `"term"` key acts as a global fallback — avoid it to prevent cross-chapter collisions.

## Flow diagrams
`<div class="flow-diagram">` renders nodes LTR (direction: ltr is set in guide.css). Write node order left→right. Do not add inline `direction: rtl` to diagram elements.

## IBM i chapter (ch. 29) key facts
- **Premium Package for i** — always "Package", never "plugin" (Tim Rowe, IBM)
- **Native Connection = SSH only** — never recommend the open-source MCP server
- **`/erd schema-name`** — slash-command in DB Mode that runs multi-threaded SQL Services queries and produces a Mermaid ERD
- **RPG Modernization Workflow** — three phases with compile gate: OPM→ILE → scan I/O specs → free-form; ends with Modernization Summary Report
- **Bob auto-corrects compile errors** — detects from *EVENTF output, patches, recompiles
- **Reports → IFS → source control** — Bob uses saved Markdown reports as future context
- **Custom Workflows/Skills/Tools** — everything is extendable; built-in workflows cannot be edited directly
