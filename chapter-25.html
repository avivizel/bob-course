מטרת הפרק

בסוף הפרק: הוכחה + איכות

מבוא

Tests = spec executable. Review = human gate + Bob assist — לא replace.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

Unit Test

מבוא

פונקציה קטנה אפשר לבדוק בלי להרים את כל המערכת.

משמעות

בדיקה מבודדת ליחידה אחת, למשל validateTitle(), עם קלט ידוע ותוצאה צפויה.

כוונה

הכוונה: לכסות לוגיקה טהורה מהר. זה לא מחליף בדיקת API.

function isolation.

דוגמה: validateTitle()
זהירות: no tests.

Integration

מבוא

יחידות ירוקות יכולות להיכשל יחד. Integration בודק חיבור.

משמעות

בדיקה שחוצה שכבות: POST באמת יוצר שורה ב-DB ומחזיר 201.

כוונה

הכוונה: לכתוב טסט מ-AC של ה-slice, לא לדמות הכול עד שאין מציאות.

API + DB.

דוגמה: POST creates row
זהירות: mock everything.

Review Checklist

מבוא

LGTM בלי רשימה מפספס אבטחה ו-AC. Checklist מיישר ביקורת.

משמעות

רשימת בדיקות ל-PR: הרשאות, SQL params, AC, סגנון, בדיקות רצות.

כוונה

הכוונה: ש-Bob יסייע לפי הצ'קליסט, והאדם עדיין חותם.

security, AC, style.

דוגמה: SQL params?
זהירות: LGTM blind.

Coverage

מבוא

100% כיסוי יכול להיות תיאטרון. Coverage שימושי על נתיבים קריטיים.

משמעות

אילו תרחישים באמת נבדקים: יצירה, שגיאת קלט, משתמש לא מורשה.

כוונה

הכוונה: להעדיף נתיב עסקי חשוב על אחוז יפה בדוח.

what's tested.

דוגמה: critical paths
זהירות: 100% vanity.
משל מהעולם האמיתי

Test שנכתב אחרי קוד בודק מה הקוד עושה — לא מה הוא צריך לעשות. AC שנכתבה לפני קוד היא ה-spec; test שנגזר ממנה בודק עמידה ב-spec. Code review ב-Bob הוא עזר, לא תחליף — המפתח הוא שמכיר את ה-business logic ורואה את מה שBob מחמיץ.

שאלות לחשיבה: מצאו path אחד ב-TaskFlow שאין לו test: כתבו AC בפורמט Given/When/Then ואז test שבודק בדיוק את ה-AC — לא את מה שהקוד כבר עושה.

Agent

Tests for AC.

Prompt לדוגמה

From @plan/create-task.md AC: write integration tests for POST /api/tasks. Run. Report.

למה זה עובד: AC → tests.

טעות נפוצה

לא: merge without tests.

כן: AC → tests → review → merge.

מעבדה מודרכת
  1. Tests for slice 1.
  2. Run CI/local.
  3. Bob review + human.
  4. Fix findings.
  5. Merge.
  6. הצלחה = unit + integration tests עוברים ב-CI, review checklist מסומן, merge ל-main.

תשובה לדוגמה: catch logic, security, AC gaps.
Coverage?
תשובה לדוגמה: critical paths > percentage.

  • Merge with proof.
