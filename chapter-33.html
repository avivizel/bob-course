ארכיטקטורת Bob SaaS — Regional Deployment ו-Data Flows

מה עובר על הקו, איפה המודלים רצים, ואיך להגן על IP

מטרת הפרק

בסוף הפרק: מה עובר על הקו, איפה המודלים רצים, ואיך להגן על IP

מבוא

Bob SaaS רץ על AWS + IBM Cloud בשלושה אזורים: ארה"ב, אירופה ויפן. כל prompt עובר דרך שכבת AuthN/AuthZ, Bob Model Gateway ו-Metering לפני שמגיע למודל. Bob תומך במגוון LLMs — IBM Granite, Claude, Llama ועוד. להבין את ה-Data Flow אומר לדעת מה יוצא מה-IDE, מה נשמר, ומה לא.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

מבוא

המושג LLMs הזמינים ב-Bob הוא אחד מאבני הבניין של הפרק.

משמעות

Bob תומך במספר מודלים: IBM Granite דרך watsonx.ai; Anthropic Claude; Meta Llama; Mistral — דרך שכבת ה-inference.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — להניח שכל המודלים זמינים בכל region ובכל חבילה — הזמינות תלויה ב-entitlement ובאזור.

דוגמה: Granite לקוד IBM ו-enterprise; Claude לניתוח ו-reasoning מורכב
זהירות: להניח שכל המודלים זמינים בכל region ובכל חבילה — הזמינות תלויה ב-entitlement ובאזור.

Regional Deployment

מבוא

המושג Regional Deployment הוא אחד מאבני הבניין של הפרק.

משמעות

Bob SaaS פרוס בשלושה אזורים: US (AWS us-east-1/us-west-1 + IBM Cloud us-east), Europe (AWS eu-central-1 + IBM Cloud eu-de/eu-gb), Japan (AWS ap-northeast-1 + IBM Cloud jp-tok). הלקוח מתחבר לאזור הקרוב — לשמירת data residency.

Bob Model Gateway

מבוא

המושג Bob Model Gateway הוא אחד מאבני הבניין של הפרק.

מה עובר על הקו

מבוא

המושג מה עובר על הקו הוא אחד מאבני הבניין של הפרק.

משמעות

Prompts + code snippets שנקראו + terminal output שצורף = inference payload. קוד שנשמר בדיסק, node_modules, .env = לא יוצא בלי @ מפורש.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — להניח שBob רואה את כל ה-repo — הוא רואה רק מה שנשלח בפועל.

Prompts + code snippets שנקראו + terminal output שצורף = inference payload. קוד שנשמר בדיסק, node_modules, .env = לא יוצא בלי @ מפורש.

דוגמה: git diff שצורף ב-@ → יוצא ל-LLM. .env שב-.bobignore → לא יוצא לעולם
זהירות: להניח שBob רואה את כל ה-repo — הוא רואה רק מה שנשלח בפועל.

AuthN + AuthZ

מבוא

המושג AuthN + AuthZ הוא אחד מאבני הבניין של הפרק.

משמעות

AuthN = SSO / API key. AuthZ = הרשאות per-tool ב-Harness. Metering = מדידת token usage לחיוב ו-governance.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לחשוב שRules ב-AGENTS.md = security enforcement. הם הכוונה — AuthZ ב-Harness היא האכיפה.

AuthN = SSO / API key. AuthZ = הרשאות per-tool ב-Harness. Metering = מדידת token usage לחיוב ו-governance.

דוגמה: SSO ארגוני → Bob IDE → Harness מחליט אילו כלים מותרים → LLM inference → audit log
זהירות: לחשוב שRules ב-AGENTS.md = security enforcement. הם הכוונה — AuthZ ב-Harness היא האכיפה.

On-Prem / Air-Gap

מבוא

המושג On-Prem / Air-Gap הוא אחד מאבני הבניין של הפרק.

משמעות

אותה ארכיטקטורה — endpoint inference הוא watsonx.ai פנימי (OpenShift) במקום inference בענן. תמונות קונטיינר מ-private registry. prompts לא יוצאים מהרשת.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לחשוב ש-air-gap = פחות יכולות. אותה לולאה, endpoint פנימי בלבד.

אותה ארכיטקטורה — endpoint inference הוא watsonx.ai פנימי (OpenShift) במקום inference בענן. תמונות קונטיינר מ-private registry. prompts לא יוצאים מהרשת.

דוגמה: Bob IDE → enterprise Harness → watsonx.ai GPU nodes (OpenShift) — NO public egress
זהירות: לחשוב ש-air-gap = פחות יכולות. אותה לולאה, endpoint פנימי בלבד.
משל מהעולם האמיתי

Bob שולח רק מה שנמצא בinference payload — קבצים שצורפו ב-@, טקסט שנכתב בprompt, ו-terminal output שנוסף. קוד שיושב בדיסק אבל לא צורף לא יוצא. .bobignore הוא ההגדרה המפורשת של לא לשלוח — בלי .bobignore, מידע רגיש עלול להגיע ל-LLM בלי כוונה דרך @ רחב.

שאלות לחשיבה: עבור הפרויקט שלכם: איזה אזור נכון? איזה מודל? מה ב-.bobignore? מי מנהל את ה-AuthZ?

עבודה עם IBM Bob
Ask

Ask לבדיקת data flow ו-.bobignore לפני כל עבודה עם קוד רגיש.

Prompt לדוגמה

In Ask mode: read .bobignore and AGENTS.md. Verify that .env, secrets/, and *.key are excluded. List what would be sent to the LLM if I attach @src/. Do not change files.

למה זה עובד: Audit data flow לפני עבודה עם IP רגיש — מה Bob רואה = מה יוצא.

טעות נפוצה

לא: להניח שBob רואה את כל ה-repo ושומר קוד בענן.

כן: רק מה שנשלח ב-@ או נקרא ע"י tool יוצא לLLM. הגנה = .bobignore + AuthZ + data residency region.

מעבדה מודרכת
  1. בדקו .bobignore — ודאו .env, secrets, *.pem חסומים.
  2. Ask: בקשו מBob לרשום מה יישלח ל-LLM אם תצרפו @src/.
  3. זהו את ה-region שהארגון שלכם משתמש בו — EU/US/JP.
  4. בדקו שה-AuthZ settings מגבילים כלים מסוכנים (rm, deploy).

תרגיל עצמאי

כתבו .bobignore מלא לפרויקט TaskFlow + AGENTS.md section על data residency ו-model choice.

בדקו את עצמכם
אילו LLMs זמינים ב-Bob?
תשובה לדוגמה: IBM Granite (granite-3-8b-instruct ועוד), Anthropic Claude 3.5 Sonnet / Claude 3 Haiku, Meta Llama 3, Mistral Large. הזמינות תלויה ב-entitlement ובאזור.
מה תפקיד Bob Model Gateway?
תשובה לדוגמה: Broker בין ה-IDE ל-LLMs — מנתב, מאמת (AuthZ), מודד (Metering) ומתעד (audit). הוא לא ה-LLM עצמו.
הבדל AuthN ל-AuthZ ב-Bob?
תשובה לדוגמה: AuthN = מי אתה (SSO/API key). AuthZ = מה מותר לך (Harness per-tool permissions).
Air-gap vs SaaS?
תשובה לדוגמה: אותה לולאה. SaaS = endpoint inference בענן. Air-gap = watsonx.ai פנימי על OpenShift. prompts לא עוזבים הרשת.

סיכום

  • LLMs: Granite · Claude · Llama · Mistral — לפי entitlement.
  • 3 regions: US / EU / JP — data residency לפי צורך.
  • Model Gateway = broker, לא LLM.
  • .bobignore + AuthZ = הגנה אמיתית.
