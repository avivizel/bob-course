מטרת הפרק

בסוף הפרק: ארכיטקטורת יעד, שיקולי פריסה עתידית ו-design thinking לסביבות מוסדרות

מבוא

סטטוס מוצר: לפי הודעת IBM הציבורית מ-28.04.2026, IBM Bob זמין כ-SaaS, ופריסת On-Prem מתוכננת לעתיד. הפרק מתאר שיקולים וארכיטקטורת יעד אפשרית לסביבות מוסדרות — ואינו מפרט מחייב של מוצר GA אלא אם מצורף source רשמי חדש יותר. ארגונים רבים בפיננסים, בריאות, ממשל ותעשייה כבדה אינם יכולים לשלוח קוד או נתונים רגישים לענן ציבורי. ארכיטקטורת יעד אפשרית: Bob IDE מתחבר ל-Gateway פנימי, ה-inference רץ על תשתית פנימית (כגון IBM Cloud Pak for Data על OpenShift עם watsonx.ai כ-inference engine), ו-prompts נשארים בתוך הרשת הארגונית. תרשימי הפרק הם Conceptual target architecture — לא confirmed Bob GA implementation.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

IBM Cloud Pak for Data (CPD)

מבוא

המושג IBM Cloud Pak for Data (CPD) הוא אחד מאבני הבניין של הפרק.

משמעות

פלטפורמת AI ו-data של IBM לפריסה On-Prem או ב-private cloud. רצה על OpenShift. מספקת את שירותי watsonx.ai, governance ו-data fabric בתוך מרכז הנתונים הארגוני.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לבלבל בין CPD (הפלטפורמה) לבין watsonx.ai (שירות ה-inference). CPD היא הכלי — watsonx.ai הוא השירות שרץ עליה.

פלטפורמת AI ו-data של IBM לפריסה On-Prem או ב-private cloud. רצה על OpenShift. מספקת את שירותי watsonx.ai, governance ו-data fabric בתוך מרכז הנתונים הארגוני.

דוגמה: CPD על RHOCP 4.14 → watsonx.ai service → Granite / Mistral / Llama on GPU nodes → Bob IDE
זהירות: לבלבל בין CPD (הפלטפורמה) לבין watsonx.ai (שירות ה-inference). CPD היא הכלי — watsonx.ai הוא השירות שרץ עליה.

watsonx.ai On-Prem Inference

מבוא

המושג watsonx.ai On-Prem Inference הוא אחד מאבני הבניין של הפרק.

משמעות

שירות ה-inference של IBM שרץ בתוך CPD. מטפל ב-model loading, GPU scheduling, API, ו-rate limiting — בדיוק כמו ב-SaaS, אבל על hardware ארגוני.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — להניח שכל המודלים מה-SaaS זמינים On-Prem — model availability תלוי ב-entitlement ובנפח ה-GPU.

שירות ה-inference של IBM שרץ בתוך CPD. מטפל ב-model loading, GPU scheduling, API, ו-rate limiting — בדיוק כמו ב-SaaS, אבל על hardware ארגוני.

דוגמה: POST https://cpd.internal/ml/v1/text/generation → Granite model → completion חוזר ל-Bob IDE

Air-Gap Deployment

מבוא

המושג Air-Gap Deployment הוא אחד מאבני הבניין של הפרק.

משמעות

סביבה ללא חיבור לאינטרנט ציבורי. Bob IDE, CPD ו-model images מגיעים דרך private registry (Artifactory, Quay, IBM ICR Mirror). אפס egress traffic.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לצפות לעדכוני מודלים אוטומטיים ב-air-gap — הם מגיעים רק דרך image pull מפורש מ-private registry.

סביבה ללא חיבור לאינטרנט ציבורי. Bob IDE, CPD ו-model images מגיעים דרך private registry (Artifactory, Quay, IBM ICR Mirror). אפס egress traffic.

דוגמה: Bob IDE → internal proxy → CPD API (no TLS pinning to IBM Cloud) → watsonx.ai GPU → completion
זהירות: לצפות לעדכוני מודלים אוטומטיים ב-air-gap — הם מגיעים רק דרך image pull מפורש מ-private registry.

Private Model Registry

מבוא

המושג Private Model Registry הוא אחד מאבני הבניין של הפרק.

משמעות

מאגר פנימי של model images ו-adapters. המודלים נמשכים פעם אחת מ-IBM ICR ומאוחסנים ב-Quay / Artifactory פנימי. כל deployment משתמש בעותק פנימי בלבד.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לשכוח לעדכן את ה-registry הפנימי כשיוצאת גרסה חדשה — המודל פנימי לא מתעדכן לבד.

Bob Model Gateway (On-Prem)

מבוא

המושג Bob Model Gateway (On-Prem) הוא אחד מאבני הבניין של הפרק.

משמעות

בסביבת On-Prem, Bob Model Gateway רץ כ-container על OpenShift. מנתב בין Bob IDE לבין watsonx.ai הפנימי. AuthN/AuthZ דרך LDAP / SAML ארגוני במקום IBM IAM.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — להשתמש ב-API key של IBM Cloud ב-On-Prem — AuthN On-Prem עובד מול IdP הארגוני, לא מול IBM IAM.

בסביבת On-Prem, Bob Model Gateway רץ כ-container על OpenShift. מנתב בין Bob IDE לבין watsonx.ai הפנימי. AuthN/AuthZ דרך LDAP / SAML ארגוני במקום IBM IAM.

דוגמה: Bob IDE → Bob Gateway Pod (OpenShift) → AuthZ (LDAP) → watsonx.ai inference → completion
זהירות: להשתמש ב-API key של IBM Cloud ב-On-Prem — AuthN On-Prem עובד מול IdP הארגוני, לא מול IBM IAM.

Data Residency ו-Compliance

מבוא

המושג Data Residency ו-Compliance הוא אחד מאבני הבניין של הפרק.

משמעות

ב-On-Prem (כיעד) כל prompts, completions ו-audit logs נשארים בתוך הרשת הארגונית. פריסה מקומית עשויה לסייע לעמוד בדרישות data residency, security ו-control — אך compliance נקבע לפי התצורה, התהליכים, הבקרות וההסמכה של הארגון, לא מעצם היות המוצר On-Prem.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לחשוב ש-Air-Gap אוטומטי ב-On-Prem — נדרשת הגדרה מפורשת של network policies ו-egress rules, וגם הסמכות compliance נפרדות.

ב-On-Prem (כיעד) כל prompts, completions ו-audit logs נשארים בתוך הרשת הארגונית. פריסה מקומית עשויה לסייע לעמוד בדרישות data residency, security ו-control — אך compliance נקבע לפי התצורה, התהליכים, הבקרות וההסמכה של הארגון, לא מעצם היות המוצר On-Prem.

GPU Requirements (Illustrative)

מבוא

המושג GPU Requirements (Illustrative) הוא אחד מאבני הבניין של הפרק.

משמעות

Inference On-Prem דורש GPU nodes. דרישות GPU תלויות במודל, precision, concurrency, latency target ו-serving stack — יש להשתמש ב-sizing guide הרשמי של גרסת המוצר.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לתכנן On-Prem בלי GPU — CPU-only מאוד איטי ל-inference ואינו מתאים לייצור.

Inference On-Prem דורש GPU nodes. דרישות GPU תלויות במודל, precision, concurrency, latency target ו-serving stack — יש להשתמש ב-sizing guide הרשמי של גרסת המוצר.

Bob + CPD — Data Flow

מבוא

המושג Bob + CPD — Data Flow הוא אחד מאבני הבניין של הפרק.

משמעות

Bob IDE → TLS (internal CA) → Bob Gateway Pod → watsonx.ai API → model inference → completion → IDE. Metering ו-audit נשמרים ב-CPD. אין egress.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — להשתמש ב-self-signed certificate ללא internal CA — Bob IDE לא יאמין לendpoint.

Bob IDE → TLS (internal CA) → Bob Gateway Pod → watsonx.ai API → model inference → completion → IDE. Metering ו-audit נשמרים ב-CPD. אין egress.

דוגמה: מפתח RPG → Developer Mode → Bob Gateway (OpenShift) → Granite (CPD) → refactoring suggestion → IDE (ללא יציאה מהרשת)
זהירות: להשתמש ב-self-signed certificate ללא internal CA — Bob IDE לא יאמין לendpoint.
משל מהעולם האמיתי

ב-SaaS, prompt עובר TLS לinfrastructure של IBM Cloud — מחוץ לרשת הארגונית. ב-On-Prem, אותו prompt עובר TLS לGateway Pod שרץ בתוך OpenShift הארגוני — ולא יוצא. ההבדל הוא לא ביכולת, אלא היכן פועלת ה-inference ומי שולט בנתונים.

שאלות לחשיבה: ב-TaskFlow: אם הפרויקט נמצא בסביבת בנק — איזה מרכיב תדרשו לאמת ראשון? מה הצעד הראשון ב-On-Prem deployment?

# AGENTS.md — Bob On-Prem Project (Conceptual)
## Deployment target: CPD on RHOCP · watsonx.ai service
## Inference endpoint: https://cpd.internal/ml/v1/... (target — verify with IBM)
## AuthN: internal IdP (LDAP/SAML — NOT IBM Cloud API key)
## Model registry: registry.internal/ibm/ (Quay/Artifactory)
## GPU: NVIDIA nodes required — sizing per IBM official guide for your version
## Network: NO public egress from inference namespace
## Audit: prompts + completions → internal SIEM
## Data residency: prompts stay in datacenter (verify with legal/compliance team)
## Rules:
- Never use IBM Cloud API key in On-Prem
- All model pulls via registry.internal only
- .bobignore: .env, secrets/, *.pem, *.key, config/prod*
- Internal CA cert required in Bob IDE trust store
מעבדה מודרכת
  1. ציירו Data Flow diagram (conceptual): Bob IDE → Gateway → inference engine → GPU → completion (ללא אינטרנט).
  2. זהו שאלות שארגון צריך לענות לפני On-Prem deployment: GPU sizing לפי sizing guide הרשמי, model availability, network egress policy.
  3. בדקו: מהן דרישות ה-GPU לפי תיעוד IBM הרשמי של הגרסה הרלוונטית?
  4. תכננו network policy: אילו namespaces מורשים לדבר עם inference engine?
  5. הכינו רשימת מודלים לייבא ל-private registry (private model list).
  6. Plan mode: בקשו מ-Bob לכתוב AGENTS.md ל-On-Prem project עם data residency requirements ושאלות פתוחות שדורשות אימות.

תרגיל עצמאי

כתבו deployment checklist מלא ל-Bob On-Prem בארגון פיננסי: CPD, GPU, registry, AuthN, network policy, audit, .bobignore.

בדקו את עצמכם
מה ההבדל בין Bob SaaS ל-Bob On-Prem מבחינת Data Flow?
תשובה לדוגמה: SaaS: prompts עוברים TLS לIBM Cloud inference. On-Prem: prompts עוברים TLS לGateway Pod ב-OpenShift — אפס egress לאינטרנט.
מה תפקיד CPD ב-On-Prem?
תשובה לדוגמה: פלטפורמת האירוח — מריצה את watsonx.ai, מנהלת GPU scheduling, AuthZ ו-metering. לא ה-inference עצמו.
למה private model registry?
תשובה לדוגמה: Air-gap: אי אפשר לפנות ל-IBM ICR ישירות. מושכים מודלים פעם אחת → שומרים פנימי → CPD pull מהregistry הפנימי.
מה עקרון ה-GPU sizing ל-On-Prem?
תשובה לדוגמה: דרישות GPU תלויות במודל, precision, concurrency ו-serving stack. יש לפנות ל-sizing guide הרשמי של גרסת המוצר — אין sizing אחיד שתקף לכל deployment.
איך AuthN שונה ב-On-Prem?
תשובה לדוגמה: SaaS: IBM IAM + API key. On-Prem: LDAP / SAML ארגוני מול Bob Gateway Pod. אין שימוש ב-IBM Cloud IAM.
