מטרת הפרק

בסוף הפרק: רעיונות לפני סימנים ושפות

מבוא

תכנות = הוראות, החלטות, חזרות ומבנים. Bob כותב תחביר; אתם צריכים להבין לוגיקה.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

משתנה

מבוא

התוכנה צריכה לזכור ערכים בשמות. משתנה הוא תווית לערך.

משמעות

שם שמחזיק נתון (מחרוזת, מספר, רשימה) ואפשר לקרוא או לעדכן אותו.

כוונה

הכוונה: לבחור שמות שמסבירים את עצמם — לכם ול-Bob — כדי שלא ינחשו.

שם לערך.

דוגמה: taskTitle = לסיים PRD
זהירות: שם לא ברור.

תנאי

מבוא

תוכנה לא עושה תמיד אותו דבר. תנאי הוא צומת החלטה.

משמעות

if / else: אם מצב מסוים מתקיים — בצע א; אחרת — בצע ב. בלי else נשארים מצבים שקטים.

כוונה

הכוונה: לשאול מה קורה אם הקלט ריק / שגוי / כפול לפני שמממשים.

if/else — בחירה.

דוגמה: if status === 'done' → hide
זהירות: בלי else — edge cases.

לולאה

מבוא

רשימת משימות דורשת אותה פעולה לכל פריט. לולאה חוזרת במקום להעתיק קוד.

משמעות

חזרה על פעולה לכל איבר ברשימה, או עד שתנאי עצירה מתקיים.

כוונה

הכוונה: לוודא שיש תנאי עצירה — לולאה אינסופית מקפיאה את האפליקציה.

חזרה על פעולה.

דוגמה: tasks.forEach(render)
זהירות: לולאה אינסופית.

פונקציה

מבוא

במקום לכתוב אותו בלוק פעמיים, נותנים לו שם. פונקציה היא יחידת עבודה.

משמעות

קוד עם שם, קלט (פרמטרים) ופלט (ערך מוחזר או פעולה). אמורה לעשות דבר אחד.

כוונה

הכוונה: לבקש מ-Bob פונקציות קצרות — קל לבדוק, קל להסביר, קל לתקן.

יחידת עבודה עם שם.

דוגמה: createTask(title)
זהירות: פונקציה שעושה 5 דברים.

הערך החוזר (return)

מבוא

המושג הערך החוזר (return) הוא אחד מאבני הבניין של הפרק.

משמעות

מה הפונקציה מחזירה — ה-output המפורש. בלי return — הפונקציה מחזירה undefined.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — פונקציה שמשנה state חיצוני במקום להחזיר ערך — קשה לבדיקה.

מה הפונקציה מחזירה — ה-output המפורש. בלי return — הפונקציה מחזירה undefined.

דוגמה: function add(a, b) { return a + b } ← הפלט הוא a+b, לא undefined
זהירות: פונקציה שמשנה state חיצוני במקום להחזיר ערך — קשה לבדיקה.

Scope

מבוא

המושג Scope הוא אחד מאבני הבניין של הפרק.

משמעות

היכן משתנה גלוי. משתנה בתוך פונקציה — לא גלוי מחוצה לה.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — הצהרה על let בתוך if — לא גלוי מחוץ לבלוק ב-JS.

היכן משתנה גלוי. משתנה בתוך פונקציה — לא גלוי מחוצה לה.

דוגמה: const total = tasks.reduce(sum, 0) — total גלוי רק בבלוק הזה
זהירות: הצהרה על let בתוך if — לא גלוי מחוץ לבלוק ב-JS.
משל מהעולם האמיתי

pseudocode מפריד בין לוגיקה לבין תחביר. כשמבינים את ה-if/else בעברית פשוטה — שגיאת compilation אינה מבלבלת: ברור שהלוגיקה נכונה, ורק הסימנים צריכים תיקון. אם לא הבנתם את ה-pseudocode — אין טעם לקרוא את הקוד.

שאלות לחשיבה: מצאו את createTask ב-TaskFlow. בקשו מ-Bob pseudocode שלה. בדקו: האם ה-pseudocode מסביר את כל ה-edge cases — כגון title ריק, משתמש לא מחובר? אם לא — הוסיפו אותם לפני שמאשרים קוד.

עבודה עם IBM Bob
Ask

Ask להסבר לוגיקה — לא קוד מלא.

Prompt לדוגמה

Explain createTask in @api/tasks.js as pseudocode. Do not change any code.

למה זה עובד: Pseudocode = הבנה בלי תחביר.

טעות נפוצה

לא: Bob כתב קוד עם if nested של 4 רמות — אישרתם כי נראה תקין.

כן: בקשו pseudocode ראשון. אם ה-pseudocode לא מובן לכם — הקוד לא יהיה תקין.

מעבדה מודרכת
  1. מצאו פונקציה ב-TaskFlow.
  2. בקשו מ-Bob pseudocode.
  3. זהו: input, output, conditions, edge cases.
  4. כתבו pseudocode משלכם לפונקציה שכתב Bob.
  5. השוו — מצאו את ההבדל.
  6. הצלחה = זיהיתם edge case אחד שהpseudocode של Bob לא כיסה.

תרגיל עצמאי

תארו מחיקת משימה ב-pseudocode — 5 שורות max.

בדקו את עצמכם
משתנה vs קבוע?
תשובה לדוגמה: משתנה משתנה; קבוע (const) — לא.
למה פונקציה קצרה?
תשובה לדוגמה: קל לבדוק, לשם, לשכפל.
תנאי בלי else?
תשובה לדוגמה: מצבים לא צפויים נשברים בשקט.
מה מחזירה פונקציה ללא return?
תשובה לדוגמה: undefined — לא שגיאה, אבל כל קוד שמשתמש בתוצאה שלה יקבל undefined בשקט.
Scope — למה זה חשוב?
תשובה לדוגמה: משתנה שמוצהר בתוך if לא גלוי אחרי הבלוק. Bob לפעמים מכריז בלוקלי ומשתמש גלובלית — בדקו scope בdiff.
