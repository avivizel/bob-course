סביבת העבודה של המפתח

IBM Bob IDE, קבצים ופקודות הפעלה

מטרת הפרק

בסוף הפרק: IBM Bob IDE, קבצים ופקודות הפעלה

מבוא

סביבת הפיתוח היא שולחן העבודה שלכם. Explorer, Editor, Terminal ו-Bob Chat — כשיודעים מה כל חלק עושה, פחות מפחדים משגיאות.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

Explorer

מבוא

לפני שעורכים קוד צריך לדעת איפה הוא יושב. Explorer הוא המפה של הפרויקט.

משמעות

עץ התיקיות והקבצים ב-IDE: app, templates, requirements.txt ועוד. כל נתיב הוא כתובת מדויקת.

כוונה

הכוונה: לצרף ל-Bob את הקובץ הנכון עם @ — אחרת הוא עלול לערוך מקום לא רלוונטי.

עץ הקבצים — מבט על מבנה הפרויקט.

דוגמה: app/, templates/, requirements.txt.
זהירות: לערוך קובץ לא נכון כי לא בדקתם נתיב.

Editor

מבוא

כאן קוראים ומשנים קוד. כל שינוי כאן הוא שינוי אמיתי בפרויקט.

משמעות

חלון העריכה ב-IDE: שורות, הדגשת תחביר, ו-Diff אחרי ש-Bob או אתם שיניתם קובץ.

כוונה

הכוונה: לא לאשר עריכה בלי לקרוא. Editor הוא המקום שבו האחריות נראית.

קריאה ועריכת קוד.

דוגמה: שינוי tasks.html.
זהירות: שינוי בלי Diff review.

Terminal

מבוא

המחשב מציית לפקודות טקסט. Terminal הוא הפתח להריץ אותן.

משמעות

חלון שמריץ python, pip, git, בדיקות ושרת מקומי. פלט השגיאה מופיע כאן.

כוונה

הכוונה: להבין פקודה לפני הרצה. Ask יכול להסביר; Terminal מבצע.

הרצת פקודות: python, pip, git, בדיקות.

דוגמה: python app.py
זהירות: הרצת פקודה לא מוכרת בלי Ask.

Build & Run

מבוא

יש הבדל בין לראות אצלכם במחשב לבין להכין גרסה ללקוח.

משמעות

Run (למשל python app.py) מפעיל סביבת פיתוח מקומית. Build או packaging מכינים תוצר לפריסה כשצריך.

כוונה

הכוונה: לא לבדוק ב-production ולא לבלבל בין הרצה מקומית לבין הכנת תוצר לפריסה.

Run = הפעלה מקומית. Build = הכנת תוצר לפריסה כשצריך.

דוגמה: python app.py → הפעלה מקומית
זהירות: לבלבל בין סביבת פיתוח לפריסה.

requirements.txt

מבוא

המושג requirements.txt הוא אחד מאבני הבניין של הפרק.

משמעות

רשימת חבילות Python בפרויקט. שם מגדירים מה צריך להתקין כדי להריץ.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — להתקין חבילה ידנית בלי לעדכן requirements.txt.

רשימת חבילות Python בפרויקט. שם מגדירים מה צריך להתקין כדי להריץ.

דוגמה: flask==3.0.0
זהירות: להתקין חבילה ידנית בלי לעדכן requirements.txt.

Error Log

מבוא

המושג Error Log הוא אחד מאבני הבניין של הפרק.

משמעות

פלט שמראה מה קרה בזמן ההרצה. ב־Python traceback קוראים קודם את שורת ה־exception האחרונה כדי לזהות את סוג השגיאה וההודעה, ואז עולים דרך ה־stack frames כדי להבין מאיפה היא הגיעה.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לקרוא רק את תחילת ה־traceback או להסתכל על שורה בודדת בלי ההקשר.

משל מהעולם האמיתי

Explorer, Editor ו-Terminal הם שלוש נקודות מבט על אותו פרויקט: מבנה, תוכן, הרצה. כשיש שגיאת הרצה — Explorer מראה היכן הקובץ, Editor מראה את השורה, Terminal מראה את הודעת השגיאה. שלושתם חייבים לעבוד יחד.

שאלות לחשיבה: פתחו requirements.txt ב-Ask ובקשו מ-Bob: אילו חבילות הפרויקט צריך, ומה יקרה אם חבילה חסרה? — קבלו תשובה מפורשת לפני שמריצים.

עבודה עם IBM Bob
Ask

Ask + קריאת קבצי תצורה בלבד.

Prompt לדוגמה

In Ask mode: read requirements.txt and README. Explain install, run, and test. Do not run any commands.

למה זה עובד: מצמצם לקבצי תצורה — פלט מדויק ובטוח.

טעות נפוצה

לא: python app.py לא עובד — מריצים pip install מ-Stack Overflow בלי לדעת מה הוא מתקין.

כן: בקשו מ-Bob: קראו requirements.txt ואמרו לי מה חסר לפי החבילות — הסיבה לפני הפתרון.

מעבדה מודרכת
  1. פתחו TaskFlow ב-Bob IDE.
  2. בקשו מ-Bob הסבר לכל חבילה ב-requirements.txt.
  3. הריצו python app.py אחרי שהבנתם מה הוא עושה.
  4. פתחו שגיאה מכוונת — מחקו חבילה — ובדקו מה מופיע בTerminal.
  5. תעדו: האם הצגתם ל-Bob את הודעת ה-exception ואת ה-traceback הרלוונטי, בלי להסתיר את ההקשר?
  6. הצלחה = הבנתם איך הפרויקט רץ בפיתוח וזיהיתם שגיאה אחת בעצמכם.

תרגיל עצמאי

מצאו 3 קבצים שלא יודעים מה תפקידם — שאלו Bob ב-Ask.

בדקו את עצמכם
הבדל קובץ מקור vs תצורה?
תשובה לדוגמה: מקור = לוגיקה/ממשק. תצורה = הגדרות (requirements.txt, .env).
מה עושה requirements.txt?
תשובה לדוגמה: מגדיר אילו חבילות Python צריך להתקין כדי שהפרויקט ירוץ בצורה עקבית.
מאיפה מתחילים לקרוא Python traceback?
תשובה לדוגמה: מזהים את סוג ה־exception וההודעה בסוף, ואז עולים דרך ה־frames כדי לאתר את מקור הבעיה.
מה ההבדל בין pip install -r requirements.txt לבין python app.py?
תשובה לדוגמה: pip install מתקין את התלויות. python app.py מפעיל את האפליקציה. אם מדלגים על ההתקנה — ההרצה עלולה להיכשל.
שגיאה ב-Terminal מדווחת על קובץ שלא מכירים — מה עושים ראשון?
תשובה לדוגמה: בקשו מ-Bob לזהות את הקובץ ב-Explorer ולהסביר תפקידו לפני כל שינוי.
