מבוא

DB = source of truth. Schema, migrations, queries — Bob עוזר, אתם מאמתים.

פרויקט Capstone — TaskFlow

SQLite: tasks table, migrations, queries.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

Schema

מבוא

בלי מבנה מוסכם הנתונים הופכים לבלגן. Schema הוא החוזה של הטבלאות.

משמעות

הגדרת טבלאות, עמודות, טיפוסים ומפתחות — למשל tasks(id, title, status).

כוונה

הכוונה: לתכנן מפתח ראשי ושדות חובה לפני ש-Bob ייצור טבלה מהר.

מבנה טבלאות.

דוגמה: tasks(id, title, status)
זהירות: no PK.

Migration

מבוא

שינוי ידני ב-DB במחשב שלכם לא קורה אצל חבר לצוות. Migration מתעד את השינוי.

משמעות

קובץ גרסה שמשנה schema בצורה חוזרת: 001_create_tasks.sql וכן הלאה.

כוונה

הכוונה: כל שינוי מבנה = migration ב-git, לא ALTER חד-פעמי בקונסול.

שינוי schema versioned.

דוגמה: 001_create_tasks.sql
זהירות: manual alter.

Query

מבוא

הנתונים חיים ב-DB. Query הוא איך קוראים וכותבים אותם.

משמעות

פעולות CRUD: INSERT, SELECT, UPDATE, DELETE, בדרך כלל עם WHERE.

כוונה

הכוונה: פרמטרים תמיד, אף פעם לא שרשור מחרוזת מקלט משתמש — זה SQL injection.

CRUD operations.

דוגמה: INSERT, SELECT WHERE
זהירות: SQL injection.

Transaction

מבוא

שתי כתיבות שרק אחת הצליחה משאירות מצב שבור. Transaction מונע את זה.

משמעות

קבוצת פעולות שמצליחות כולן או מבוטלות כולן: BEGIN … COMMIT / ROLLBACK.

כוונה

הכוונה: לעטוף שינויים תלויים זה בזה, במיוחד כש-Agent נוגע בכמה טבלאות.

all or nothing.

דוגמה: BEGIN…COMMIT
זהירות: partial write.
משל מהעולם האמיתי

Migration היא שינוי schema עם גיבוי מובנה — כל שינוי מתועד, ניתן לחזרה וניתן להרצה מחדש בסביבה חדשה. ALTER TABLE ידני מוביל לסביבות לא מסונכרנות: staging שונה מ-production שונה מ-local, ובאגים שמתרחשים רק בproduction.

שאלות לחשיבה: בדקו את טבלת tasks של TaskFlow: האם יש index על עמודת status? על user_id? הסבירו מתי query על open tasks של user יהיה איטי בלי index.

עבודה עם IBM Bob
Agent

Migration file + test.

Prompt לדוגמה

Create migration 001_tasks.sql + repository layer. Parameterized queries only.

למה זה עובד: Safe SQL.

טעות נפוצה

לא: string concat SQL.

כן: parameterized queries.

מה Bob יכול לעשות — ומה אתם חייבים להבין

Bob יכול:

  • לכתוב schema
  • query
  • migration

האדם חייב להבין:

  • table
  • key
  • relationship
  • transaction
  • why parameterized query matters
  • data loss risk
מעבדה מודרכת
  1. Schema design.
  2. Migration.
  3. CRUD repo.
  4. Test insert/select.
  5. Commit.
  6. הצלחה = migration 001 רץ ב-fresh DB, test insert+select עובר, parameterized queries בלבד.

תרגיל עצמאי

Query: open tasks only.

בדקו את עצמכם
Migration?
תשובה לדוגמה: reproducible schema changes.
SQL injection?
תשובה לדוגמה: params — never concat input.
PK?
תשובה לדוגמה: unique id per row.

סיכום

  • Schema explicit.
  • Migrations.
  • Parameterized.
  • Repo layer.
