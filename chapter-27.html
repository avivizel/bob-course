ארכיטקטורה, פריסה ותפעול

מקומי → production

מטרת הפרק

בסוף הפרק: מקומי → production

מבוא

Deploy = artifact + env + monitor. Logs, health check, rollback plan.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

Build Artifact

מבוא

העתקת קבצים ידנית לשרת אינה פריסה. Artifact הוא חבילה קפואה.

משמעות

תוצר בניה זהה לכל סביבה: תיקיית dist או docker image עם גרסה.

כוונה

הכוונה: לבנות פעם אחת ולקדם את אותו תוצר מ-staging ל-prod.

immutable deploy unit.

דוגמה: docker image
זהירות: copy files manual.

Environment

מבוא

מה שעובד אצלכם עם .env מקומי עלול להיכשל אצל הלקוח.

משמעות

הפרדת dev / staging / prod: משתנים, מפתחות, כתובות DB שונות.

כוונה

הכוונה: לא לבדוק על production. Staging קודם, עם אותם ארטיפקטים.

dev/staging/prod.

דוגמה: משתני סביבה שונים
זהירות: prod test.

Health Check

מבוא

שרת רץ אבל DB מת — המשתמש עדיין נכשל. Health אומר את האמת.

משמעות

נתיב /health שמחזיר 200 רק אם התלויות הקריטיות חיות (למשל ping ל-DB).

כוונה

הכוונה: לתת לאורקסטרציה לדעת מתי להחליף מופע, לא לנחש לפי CPU.

/health → 200.

דוגמה: DB ping
זהירות: no monitor.

Rollback

מבוא

פריסת יום שישי בלי תוכנית חזרה היא הימור. Rollback הוא התוכנית.

משמעות

החזרת הגרסה הקודמת במהירות: redeploy של artifact קודם, לא לתקן live.

כוונה

הכוונה: לתרגל rollback לפני פרוד. נוהל שלא נוסה אינו נוהל.

previous version.

דוגמה: redeploy v1.2
זהירות: no backup.
משל מהעולם האמיתי

Deploy לproduction ללא staging הוא הוכחת production — המשתמשים הם ה-QA. Health check ב-/health + rollback מתועד מבדיל בין deploy עם רשת ביטחון לבין deploy שדורש hotfix בשעה 2 בלילה.

שאלות לחשיבה: הגדירו את ה-staging environment של TaskFlow: URL, משתני סביבה שונים מ-prod, ו-smoke test של 3 בדיקות שחייבות לעבור לפני deploy ל-production.

עבודה עם IBM Bob
Plan

Deploy plan doc.

Prompt לדוגמה

Plan TaskFlow deploy: artifact, env vars, health, rollback, monitoring. No deploy yet.

למה זה עובד: Ops readiness.

טעות נפוצה

לא: deploy Friday, no rollback.

כן: staging → smoke → prod + rollback.

מעבדה מודרכת
  1. Deploy plan.
  2. Health endpoint.
  3. Staging deploy.
  4. Smoke test.
  5. Runbook draft.
  6. הצלחה = staging deployed, /health מחזיר 200, smoke test עובר, runbook עם 3 scenarios כתוב.

תרגיל עצמאי

Runbook: DB down — 5 steps.

בדקו את עצמכם
Artifact?
תשובה לדוגמה: same build all envs.
Health check?
תשובה לדוגמה: orchestrator knows alive.
Rollback?
תשובה לדוגמה: tested procedure.

סיכום

  • Plan deploy.
  • Staging first.
  • Health + logs.
  • Rollback tested.
