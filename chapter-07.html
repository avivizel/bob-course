Prompt ברור, מוגבל וניתן לבדיקה

מטרת הפרק

בסוף הפרק: Prompt ברור, מוגבל וניתן לבדיקה

מבוא

Prompt טוב = הזמנת עבודה: Context, Goal, Constraints, Acceptance Criteria. זה ההבדל בין demo ל-production.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

Context

מבוא

Prompt בלי הקשר הוא הזמנה לניחוש. Context אומר ל-Bob איפה לעבוד.

משמעות

רקע המשימה והקבצים הרלוונטיים, בדרך כלל עם @path, כדי לצמצם את שדה הראייה.

כוונה

הכוונה: לצרף רק מה שדרוש. יותר מדי קבצים מבלבל; פחות מדי גורם להמצאות.

רקע + @קבצים.

דוגמה: @src/tasks/
זהירות: בלי קונטקסט בוב מנחש.

Goal

מבוא

תשפר אינו יעד. Goal הוא תוצאה אחת שאפשר להצביע עליה בסוף.

משמעות

תיאור קצר של מה צריך להיות נכון כשמסיימים — פיצ'ר אחד, לא רשימת משאלות.

כוונה

הכוונה: בקשה אחת = תוצאה אחת. כמה יעדים באותו prompt מייצרים בלגן.

תוצאה אחת.

דוגמה: סינון All/Open/Done
זהירות: 3 features בבקשה.

Constraints

מבוא

מה שאסור חשוב כמו מה שרוצים. Constraints חוסמים סטייה.

משמעות

גבולות: טכנולוגיה מותרת, קבצים שאסור לגעת, ספריות חדשות אסורות, Out of scope.

כוונה

הכוונה: למנוע מ-Bob לשדרג הכל בדרך. הוא אופטימי אם לא עוצרים אותו.

מה אסור.

דוגמה: בלי ספרייה חדשה
זהירות: לא לציין out of scope.

Acceptance Criteria

מבוא

בלי קריטריון מדיד אי אפשר לדעת אם סיימנו. AC הופך יעד לבדיקה.

משמעות

תנאים שניתן לאמת: מצבים במסך, קוד סטטוס, בדיקה שעוברת, התנהגות לחיצה.

כוונה

הכוונה: לכתוב AC לפני Agent. שיעבוד יפה אינו קריטריון.

תנאים מדידים.

דוגמה: 3 מצבים + tests
זהירות: שיעבוד.

Out of Scope

מבוא

המושג Out of Scope הוא אחד מאבני הבניין של הפרק.

משמעות

הצהרה מפורשת על מה לא לגעת בו.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — להשאיר implicit — Bob ישנה גם Backend אם לא נאמר אחרת.

הצהרה מפורשת על מה לא לגעת בו.

דוגמה: Out of scope: לא לשנות @api/tasks.js — רק UI
זהירות: להשאיר implicit — Bob ישנה גם Backend אם לא נאמר אחרת.

Prompt Iteration

מבוא

המושג Prompt Iteration הוא אחד מאבני הבניין של הפרק.

משמעות

Prompt ראשון לעולם לא מושלם — זו טיוטה. Plan review חושף מה לתקן לפני Agent.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לאשר Plan v1 מבלי לעדכן — Agent מממש את הטיוטה.

Prompt ראשון לעולם לא מושלם — זו טיוטה. Plan review חושף מה לתקן לפני Agent.

דוגמה: Prompt v1 → Plan → חסר migration mention → Prompt v2 → Plan מתוקן → Agent
זהירות: לאשר Plan v1 מבלי לעדכן — Agent מממש את הטיוטה.
משל מהעולם האמיתי

מודל שפה מייצר את הפלט הסביר ביותר לפי הקלט שקיבל. Context חסר → הנחות. Goal עמום → scope creep. ללא Acceptance Criteria — אי אפשר לדעת אם התוצאה נכונה עד שבודקים ידנית. CGCA הוא המינימום שהופך בקשה לניתנת לבדיקה.

שאלות לחשיבה: כתבו CGCA ל-סינון Done ב-TaskFlow. שלחו ל-Bob ב-Plan. קראו את ה-Plan — מצאו item אחד שBob הניח ולא ציינתם. תקנו את ה-CGCA ושלחו שוב.

Plan

CGCA template לכל בקשה.

Prompt לדוגמה

Context: @src/tasks
Goal: Add All / Open / Done filter
Constraints: vanilla JS, no new libraries
AC: all three states work + a unit test
Show a Plan before editing.

למה זה עובד: CGCA = ניתן לבדיקה.

טעות נפוצה

לא: CGCA עם AC שכתוב הסינון יעבוד — Bob לא יכול לבדוק מה זה אומר.

כן: AC: כפתור Done מסנן רשימה ל-tasks עם status=done בלבד; כפתור All מחזיר הכל; unit test לכל state.

מעבדה מודרכת
  1. כתבו Prompt שורה אחת ל-TaskFlow filter.
  2. זהו 3 חסרים (Context/Goal/Constraints/AC).
  3. הרחיבו ל-CGCA מלא.
  4. שלחו ל-Plan — קראו Plan.
  5. תקנו Prompt לפי Plan.
  6. הצלחה = AC שלכם testable: כן/לא, מספר מדויק, מצב קצה אחד לפחות.

תרגיל עצמאי

CGCA ל-מחיקת משימה עם אישור.

בדקו את עצמכם
AC מדיד?
תשובה לדוגמה: כן/לא, מספר, test — לא יפה.
Out of Scope?
תשובה לדוגמה: מונע scope creep.
מתי @?
תשובה לדוגמה: כשיש קובץ/תיקייה ספציפיים.
מדוע Prompt iteration הכרחי?
תשובה לדוגמה: Prompt ראשון = טיוטה. Plan חושף הנחות. רק אחרי תיקון Prompt מבוסס Plan, הAgent מממש נכון.
Out of Scope implicit vs explicit?
תשובה לדוגמה: Implicit = Bob משנה מה שנראה לו רלוונטי. Explicit = Do not touch @api/ — גבול פיזי שBob מכבד.
