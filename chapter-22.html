MCP, כלים ו-Workflows

Bob + מערכות חיצוניות

מטרת הפרק

בסוף הפרק: Bob + מערכות חיצוניות

מבוא

MCP = Model Context Protocol — כלים מcontrolled ל-Bob (DB, API, files). Workflows = רצף מוגדר.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

MCP Server

מבוא

Bob צריך כלים למערכות חיצוניות, אבל לא מפתח מנהל לכל דבר.

משמעות

שרת Model Context Protocol שמספק כלים מוגדרים: קריאת DB, API, קבצים.

כוונה

הכוונה: לחבר MCP עם הרשאות מינימליות — עדיף read-only מול staging, לא admin ל-prod.

tool provider.

דוגמה: DB read-only MCP
זהירות: full admin MCP.

Tool Scope

מבוא

כלי שיכול DROP TABLE אינו כלי בטוח לסוכן. Scope מגביל פעולות.

משמעות

רשימת הפעולות המותרות בכלי: למשל SELECT בלבד, בלי DELETE/DROP.

כוונה

הכוונה: לבדוק כל כלי לפני חיבור: מה הוא יכול לשבור אם Bob טועה.

allowed operations.

דוגמה: SELECT only
זהירות: DROP allowed.

Workflow

מבוא

רצף אד-הוק משתנה בכל פעם. Workflow הוא סדר קבוע שאפשר לבדוק.

משמעות

שלבים ממוספרים: lint → test → report, עם קלט ופלט ברורים.

כוונה

הכוונה: להפוך עבודה חוזרת לרצף, לא לשיחה חדשה בכל שבוע.

ordered steps.

דוגמה: lint → test → report
זהירות: ad hoc.

Audit

מבוא

אם אי אפשר לדעת מי הריץ כלי — אי אפשר לחקור תקלה או אירוע.

משמעות

רישום קריאות כלים: מי, מתי, איזה כלי, איזה פרמטרים (בלי סודות).

כוונה

הכוונה: לחייב לוג ל-MCP. בלי audit אין ממשל.

log tool calls.

דוגמה: who queried what
זהירות: no logs.
משל מהעולם האמיתי

MCP tool עם הרשאות write לDB בproduction הוא גרסת AI של DROP TABLE בלי undo. כל tool שנרשם ל-Bob מוסיף קצה התקפה פוטנציאלי. read-only MCP על staging הוא ההפרש בין ניסוי מבוקר לבין תקלה בלתי הפיכה.

שאלות לחשיבה: רשמו את ה-MCP tools ש-TaskFlow Bob ישתמש בהם: לכל tool — scope (read/write), סביבה (staging/prod), ואיזה audit log נדרש. ודאו שאין write ל-prod.

עבודה עם IBM Bob
Ask

Understand MCP catalog.

Prompt לדוגמה

List MCP tools available. For each: capability, risk, least privilege recommendation.

למה זה עובד: Tool governance.

טעות נפוצה

לא: MCP with write to prod.

כן: read-only staging MCP.

מעבדה מודרכת
  1. Inventory MCP tools.
  2. Risk table.
  3. Workflow diagram.
  4. Audit requirement.
  5. הצלחה = טבלת risk עם כל MCP tool, scope מינימלי מוגדר לכל אחד ו-workflow diagram ב-docs/.

תרגיל עצמאי

Workflow: release check — 4 steps.

תשובה לדוגמה: standard for AI tools.
Tool scope?
תשובה לדוגמה: minimum ops.
Audit?
תשובה לדוגמה: compliance + debug.

סיכום

  • MCP = controlled tools.
  • Least privilege.
  • Workflows explicit.
  • Audit logs.
