Git ורשת הביטחון

ניהול גרסאות — להבין שינוי ולחזור אחורה

מטרת הפרק

בסוף הפרק: ניהול גרסאות — להבין שינוי ולחזור אחורה

מבוא

Git הוא מחברת תיעוד של כל שינוי. עם Bob שעובד מהר, Git הוא רשת הביטחון — commit קטן, הודעה ברורה, אפשרות rollback.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

Commit

מבוא

Git זוכר נקודות בזמן. Commit הוא צילום מצב עם הודעה למה שיניתי.

משמעות

יחידת שינוי שמורה בהיסטוריה, עם הודעה קצרה. אפשר לחזור אליה.

כוונה

הכוונה: commit קטן וממוקד — קל לבדוק, קל לבטל, קל להסביר לצוות.

צילום מצב עם הודעה.

דוגמה: feat: add task filter
זהירות: commit ענק עם 20 שינויים.

Branch

מבוא

לא כל ניסוי צריך לשבור את הגרסה היציבה. Branch הוא מסלול נפרד.

משמעות

קו פיתוח מקביל ל-main. עובדים שם, בודקים, ורק אז ממזגים.

כוונה

הכוונה: לבודד עבודה של Bob או פיצ'ר חדש עד שיש ראיות שהוא תקין.

קו פיתוח נפרד.

דוגמה: feature/task-filter
זהירות: לעבוד ישירות על main בלי בדיקה.

Diff

מבוא

סיימתי אינו ראיה. Diff מראה בדיוק מה השתנה.

משמעות

השוואת שורות: מה נוסף, מה נמחק, באילו קבצים. זה כלי הביקורת המרכזי.

כוונה

הכוונה: לקרוא Diff לפני commit, לפני merge, ולפני אישור עבודת Agent.

השוואה לפני/אחרי.

דוגמה: git diff
זהירות: לא לקרוא Diff לפני commit.

Rollback

מבוא

טעות תקרה. Rollback הוא היכולת לחזור בלי פאניקה.

משמעות

חזרה ל-commit או לגרסה קודמת (למשל git revert) כשהכיוון נכשל.

כוונה

הכוונה: ליצור נקודת חזרה לפני Agent — אחרת אין לאן ליפול.

חזרה לגרסה תקינה. לפני commit: git restore . | אחרי commit: git revert

דוגמה: git restore . לביטול שינויים מקומיים
זהירות: למחוק היסטוריה ב-force push.

Commit Message

מבוא

המושג Commit Message הוא אחד מאבני הבניין של הפרק.

משמעות

תיאור השינוי בפורמט type: subject. ה-type הנפוץ: feat, fix, refactor, docs, test.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — update או wip — חסרי ערך בלי subject ספציפי.

תיאור השינוי בפורמט type: subject. ה-type הנפוץ: feat, fix, refactor, docs, test.

דוגמה: fix: prevent duplicate task on double-submit
זהירות: update או wip — חסרי ערך בלי subject ספציפי.

.gitignore

מבוא

המושג .gitignore הוא אחד מאבני הבניין של הפרק.

משמעות

רשימת קבצים שGit לא עוקב אחריהם. חיוני לסינון .env, node_modules, build artifacts.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לשכוח להוסיף .env ל-.gitignore לפני commit ראשון.

רשימת קבצים שGit לא עוקב אחריהם. חיוני לסינון .env, node_modules, build artifacts.

דוגמה: .env לא נכנס ל-repo — מונע חשיפת secrets
זהירות: לשכוח להוסיף .env ל-.gitignore לפני commit ראשון.
משל מהעולם האמיתי

commit הוא checkpoint — נקודת חזרה ידועה. בלי commit לפני שינוי גדול של Bob, ה-diff מכסה עשרות קבצים בבת אחת ואי אפשר לדעת מה שייך לשינוי המתוכנן ומה הוסיף Bob מיוזמתו. Rollback הופך ל-מחיקת הכל במקום חזרה לנקודה X.

שאלות לחשיבה: לפני שמבקשים מ-Bob שינוי: הריצו git status ו-git diff ב-Ask. אם אין clean working tree — commitו ראשון. בדקו: האם commit message מסביר למה, לא רק מה?

עבודה עם IBM Bob
AskAgent

Agent רק אחרי commit; שינויים קטנים.

Prompt לדוגמה

Show git status and git diff. Summarize changes in one line per file. Do not commit.

למה זה עובד: מכריח review לפני פעולה.

טעות נפוצה

לא: תתקן הכל בלי commit — אין נקודת חזרה. Bob שינה 12 קבצים; לא ברור מה נדרש ומה יוזמה.

כן: commit clean → prompt מוגדר → שינוי אחד → diff → commit עם הסבר.

מעבדה מודרכת
  1. git init / clone TaskFlow.
  2. commit ראשון: init: add TaskFlow project structure.
  3. בקשו מ-Bob שינוי קטן ב-CSS.
  4. הריצו git diff — קראו כל שינוי.
  5. commitו עם message שמסביר את הסיבה.
  6. הצלחה = git log מראה שני commits עם messages מובנים, וה-diff של כל commit ברור.

תרגיל עצמאי

צרו branch, שינוי, merge — תעדו כל שלב.

בדקו את עצמכם
מתי commit?
תשובה לדוגמה: אחרי יחידת עבודה שלמה ונבדקת — לא באמצע.
למה Diff לפני Agent?
תשובה לדוגמה: לראות בדיוק מה השתנה — לא לסמוך על סיימתי.
Branch vs main?
תשובה לדוגמה: Branch = ניסוי מבודד; main = יציב.
commit message טוב נראה איך?
תשובה לדוגמה: type: subject קצר ומדויק. fix: prevent duplicate task on double-submit — לא update או changes.
למה .gitignore חייב להיות בcommit הראשון?
תשובה לדוגמה: אם .env נכנס ל-repo — secrets דולפים לhistory גם אחרי מחיקה. git filter-branch מורכב ואינו פתרון מושלם.

סיכום

  • Commit קטן = rollback קל.
  • Diff הוא חבר — לא אויב.
  • Bob + Git = מהירות + ביטחון.
  • אל ת-force push ל-main.
