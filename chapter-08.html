Context, /init ו-AGENTS.md

זיכרון פרויקט מדויק ומתוחזק

מטרת הפרק

בסוף הפרק: זיכרון פרויקט מדויק ומתוחזק

מבוא

שיחה חדשה = הקשר מוגבל. יש הבדל בין מה Bob רואה עכשיו (@ ו-Prompt) לבין מה שנטען מ-AGENTS.md בכל שיחה. /init מייצר טיוטה — חובה לבדוק ולתחזק. חשוב: AGENTS.md צריך להיות קצר — הוא נטען לחלון ההקשר בכל שיחה ומתחרה על מקום.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

/init

מבוא

שיחה חדשה מתחילה כמעט ריקה. /init סורק את הפרויקט ומייצר קבצי התמצאות.

משמעות

פקודה שקוראת את המבנה, ה-stack והפקודות, ויוצרת טיוטת הקשר (למשל AGENTS.md).

כוונה

הכוונה: לטפל בפלט כטיוטה. לא לסמוך על גרסאות ופקודות בלי אימות מול הקבצים.

סריקה + יצירת context files.

דוגמה: AGENTS.md + .bob/rules-code/ + rules-plan/ + rules-ask/
זהירות: להניח שהכל נכון.

AGENTS.md

מבוא

עובד חדש מקבל דף חפיפה. AGENTS.md הוא דף החפיפה של Bob.

משמעות

מסמך קצר: מטרת הפרויקט, מבנה, פקודות, כללי עבודה, ומה אסור להסיק מהקוד.

כוונה

הכוונה: לתחזק אותו. מסמך שגוי גורם ל-Bob חכם לפעול לא נכון בעקביות.

מדריך: מטרה, מבנה, כללים. קצר = יעיל. ארוך מדי = Bob מתעלם ממה שקבור בסוף.

דוגמה: TaskFlow = task manager
זהירות: AGENTS.md ישן או עמוס מדי.

Context Budget

מבוא

המושג Context Budget הוא אחד מאבני הבניין של הפרק.

משמעות

לחלון ההקשר יש גודל מוגבל. יותר קבצים ≠ תוצאות טובות יותר.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לצרף הכל בתקווה שBob יבין טוב יותר.

לחלון ההקשר יש גודל מוגבל. יותר קבצים ≠ תוצאות טובות יותר.

דוגמה: AGENTS.md קצר + @קובץ ספציפי עדיף על @כל-הפרויקט
זהירות: לצרף הכל בתקווה שBob יבין טוב יותר.

תחזוקה

מבוא

הפרויקט משתנה. ההקשר חייב להשתנות איתו, אחרת Bob עובד לפי מפה ישנה.

משמעות

עדכון AGENTS.md, rules ופקודות אחרי שינוי stack, מבנה תיקיות או כלל עסקי.

כוונה

הכוונה: לקבוע רגע עדכון — אחרי כל slice משמעותי, לא פעם בהתחלה.

עדכון אחרי שינוי stack.

דוגמה: הוספת Flask → עדכון AGENTS
זהירות: init פעם אחת.

Rules vs AGENTS.md

מבוא

המושג Rules vs AGENTS.md הוא אחד מאבני הבניין של הפרק.

משמעות

AGENTS.md = מה הפרויקט הוא. Rules (.bob/rules-*/) = איך Bob מתנהג בו. שניהם נטענים בכל שיחה — שניהם גוזלים context.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לשים הכל ב-AGENTS.md — Rules שייכות לקובץ rules, לא ל-AGENTS.

AGENTS.md = מה הפרויקט הוא. Rules (.bob/rules-*/) = איך Bob מתנהג בו. שניהם נטענים בכל שיחה — שניהם גוזלים context.

דוגמה: AGENTS: Stack: Python+SQLite. Rule: תמיד הרץ tests לפני done.
זהירות: לשים הכל ב-AGENTS.md — Rules שייכות לקובץ rules, לא ל-AGENTS.

Staleness

מבוא

המושג Staleness הוא אחד מאבני הבניין של הפרק.

משמעות

AGENTS.md שמתאר stack ישן — Bob מבוסס על הנחות שגויות.

כוונה

הכוונה: להבין מתי להשתמש בו, ומה משתבש אם מתעלמים — לא לעדכן AGENTS אחרי שינוי stack — התוצאה: קוד שנראה נכון, לא עובד בפרודקשן.

AGENTS.md שמתאר stack ישן — Bob מבוסס על הנחות שגויות.

דוגמה: AGENTS: DB: SQLite — בפועל מיגרתם ל-PostgreSQL. Bob מייצר SQLite-specific queries.
זהירות: לא לעדכן AGENTS אחרי שינוי stack — התוצאה: קוד שנראה נכון, לא עובד בפרודקשן.
משל מהעולם האמיתי

בכל שיחה חדשה, Bob מתחיל בלי היסטוריה — הוא קורא את AGENTS.md מחדש. קובץ ארוך ולא מדויק פוגע פעמיים: הוא תופס context budget יקר, ומוביל Bob לפעול על הנחות ישנות. AGENTS.md מדויק + קצר = השקעה שמשתלמת בכל שיחה.

שאלות לחשיבה: בקשו מ-Bob: קרא AGENTS.md ואת requirements.txt — רשום רק את הסתירות. כמה מצאתם? תקנו אותם ידנית.

עבודה עם IBM Bob
Ask

השוואת AGENTS.md למציאות.

Prompt לדוגמה

Read AGENTS.md and compare it to requirements.txt and the project tree. List inaccuracies only. Do not change files.

למה זה עובד: Audit לפני trust.

טעות נפוצה

לא: AGENTS.md עם 40 שורות שמתארות כל קובץ בפרויקט — Bob מתעלם מהחצי השני.

כן: AGENTS.md של 15 שורות: stack, commands, 3 כללים עסקיים קריטיים, ומה Bob לא יכול לדעת מהקוד.

הרחבה: חוברת הקשר וזיכרון

ארבע שכבות הקשר, מה לשים ב־Prompt מול AGENTS.md, ותבנית TaskFlow:

# TaskFlow
## Stack: Python, Flask, SQLite, Vanilla JS
## Commands: python app.py | pytest
## Rules: Agent must run tests before done
## Business: task status = open | done only
מעבדה מודרכת
  1. הריצו /init על TaskFlow.
  2. בקשו מ-Bob לבדוק AGENTS.md מול requirements.txt.
  3. מצאו סתירה אחת לפחות.
  4. הוסיפו כלל עסקי שלא ניתן ללמוד מהקוד.
  5. commitו AGENTS.md מעודכן.
  6. הצלחה = AGENTS.md קצר מ-20 שורות, מדויק, ומכיל לפחות מידע עסקי אחד שאינו בקוד.
