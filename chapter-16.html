מטרת הפרק

בסוף הפרק: התנהגות ורכיבים

מבוא

JS = אירועים + DOM + fetch. רכיב = UI+logic קטן (TaskItem, TaskForm).

פרויקט Capstone — TaskFlow

JS: fetch tasks, render list, handle submit.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

Event Handler

מבוא

המסך מתעורר כשמשהו קורה: שליחה, לחיצה, הקלדה. Handler הוא התגובה.

משמעות

פונקציה שרצה בעקבות אירוע DOM. בטופס חייבים preventDefault כדי לא לרענן את הדף.

כוונה

הכוונה: לחבר אירוע אחד לפעולה אחת ברורה, ולא לשרשר לוגיקה עסקית בתוך ה-onclick.

תגובה לפעולה.

דוגמה: submit → createTask
זהירות: no preventDefault.

DOM Update

מבוא

הנתונים משתנים — המסך חייב להשתקף. עדכון DOM הוא הציור מחדש.

משמעות

בניית האלמנטים מתוך נתונים (רשימת משימות). innerHTML עם קלט משתמש עלול לפתוח XSS.

כוונה

הכוונה: לרנדר מ-state, ולהימנע מהזרקת HTML גולמי ממשתמש.

render from data.

דוגמה: tasks.map → li
זהירות: innerHTML XSS.

Component

מבוא

קובץ אחד של 500 שורות נשבר מהר. רכיב הוא לבנה לשימוש חוזר.

משמעות

יחידת UI+לוגיקה עם אחריות צרה: TaskItem, TaskForm, TaskList.

כוונה

הכוונה: לבקש מ-Bob רכיב אחד לאיטרציה, לא לשכתב את כל ה-UI.

יחידה לשימוש חוזר.

דוגמה: renderTaskItem(task)
זהירות: god file.

State

מבוא

אם הסטטוס של הסינון מפוזר בשלושה מקומות, הבאגים כפולים.

משמעות

המידע שמניע את המסך כרגע: רשימת משימות, פילטר פעיל, טופס פתוח.

כוונה

הכוונה: מקור אמת אחד ל-state. פיזור יוצר חוסר סנכרון בין מסך לנתונים.

מידע UI.

דוגמה: filter = 'open'
זהירות: state scattered.
משל מהעולם האמיתי

Component ניתן לבדיקה, לשימוש חוזר ולהחלפה בנפרד. קובץ app.js של 500 שורות מחייב קריאת הכל כדי לשנות דבר אחד. מודולים (api.js, ui.js, state.js) מאפשרים לעבוד על חלק אחד בלי לפגוע בשאר.

שאלות לחשיבה: פצלו את app.js של TaskFlow לשלושה קבצים: api.js (fetch), ui.js (render), app.js (wiring). רשמו מה שייך לכל קובץ לפני שמתחילים.

עבודה עם IBM Bob
Agent

One component per iteration.

Prompt לדוגמה

Implement TaskList render from @api. No new libs. Tests for empty list.

למה זה עובד: Component scope.

טעות נפוצה

לא: 500 lines app.js.

כן: modules: api.js, ui.js, app.js.

מעבדה מודרכת
  1. Event wiring.
  2. Fetch + render.
  3. Component extract.
  4. Test empty.
  5. Commit.
  6. הצלחה = רשימת משימות מ-fetch, הוספת משימה עובדת, test empty list עובר.

תרגיל עצמאי

Split app.js — 3 modules.

XSS?
תשובה לדוגמה: escape user input in DOM.
Component?
תשובה לדוגמה: reuse + test isolation.
