Stories, קריטריוני קבלה ו-Vertical Slice

חלקים קטנים עם ערך

מטרת הפרק

בסוף הפרק: חלקים קטנים עם ערך

מבוא

User Story + AC = חוזה. Vertical Slice = feature שלם end-to-end — לא שכבה בודדת.

פרויקט Capstone — TaskFlow

Story: כמשתמש, אני יוצר משימה ורואה אותה ברשימה.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

User Story

מבוא

משימה טכנית (בנה טבלה) שוכחת את האדם. Story מחזירה אותו.

משמעות

As a [user], I want [capability], so that [value]. יחידת ערך למשתמש, לא שכבת קוד.

כוונה

הכוונה: לפרק את ה-PRD לסיפורים קטנים שאפשר לממש ולבדוק בנפרד.

As a… I want… So that…

דוגמה: As user, create task, see in list
זהירות: technical story.

Acceptance Criteria

מבוא

Story בלי AC נשארת סיפור. AC הופך אותה לחוזה בדיקה.

משמעות

Given / When / Then: מצב התחלה, פעולה, תוצאה נראית. אפשר לכתוב ממנה טסט.

כוונה

הכוונה: לכתוב AC לפני Plan. Agent בלי AC ממציא הגדרת סיום.

Given/When/Then.

דוגמה: Given empty list, when add, then shows 1 item
זהירות: vague AC.

Vertical Slice

מבוא

שבוע רק על DB לא נותן ערך למשתמש. Slice אנכי חוצה את כל השכבות.

משמעות

פיצ'ר שלם מקצה לקצה: UI → API → DB, שאפשר להדגים במסך.

כוונה

הכוונה: לבנות ב-TaskFlow קודם יצירת משימה מלאה, לא כל ה-backend.

UI→API→DB במכה.

דוגמה: create task E2E
זהירות: רק DB week 1.

INVEST

מבוא

Story ענקית (כל המערכת) לא זזה. INVEST בודק אם הסיפור בריא.

משמעות

Independent, Negotiable, Valuable, Estimable, Small, Testable — מדד לאיכות story.

כוונה

הכוונה: לפצל כשחסר Small או Testable. Epic אינו story.

Independent, Negotiable, Valuable, Estimable, Small, Testable — 6 תכונות של story טובה.

דוגמה: story קטנה שניתן להעריך ולבדוק
זהירות: epic as story.
משל מהעולם האמיתי

Vertical Slice אחד שעובד end-to-end — UI, API ו-DB — מוכיח שהארכיטקטורה עצמה עובדת. Horizontal slice (שבוע של DB בלבד) לא מוכיח כלום עד שמחברים את שאר השכבות. בעיות אינטגרציה מתגלות מוקדם ב-vertical, לא ב-sprint האחרון.

שאלות לחשיבה: הגדירו את ה-Slice הראשון ל-TaskFlow: שם, שכבות (UI/API/DB), ו-AC אחת שתוכיח שהוא עבד.

עבודה עם IBM Bob
Plan

Stories from PRD.

Prompt לדוגמה

From the PRD: write 3 user stories with acceptance criteria and a vertical-slice order. No code.

למה זה עובד: Plan backlog.

טעות נפוצה

לא: בנה backend — לא slice.

כן: create task — UI+API+DB.

מעבדה מודרכת
  1. 3 stories מ-PRD.
  2. AC לכל אחת.
  3. בחר slice 1.
  4. Plan.
  5. הצלחה = שלוש stories עם Given/When/Then מלאים ו-slice ראשון שסגור ע"י AC בלבד.

תרגיל עצמאי

Story + AC ל-סימון Done.

בדקו את עצמכם
Vertical vs Horizontal?
תשובה לדוגמה: Vertical = E2E value; Horizontal = layer only.
AC טוב?
תשובה לדוגמה: Given/When/Then — testable.
Story גדולה?
תשובה לדוגמה: Split — INVEST.

סיכום

  • Story = חוזק.
  • Slice = value.
  • AC לפני Agent.
  • Slice 1 = create task.
