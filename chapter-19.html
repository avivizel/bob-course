Full Stack, זהות והרשאות

חיבור שכבות + הגנה

מטרת הפרק

בסוף הפרק: חיבור שכבות + הגנה

מבוא

Full stack = flow שלם + auth. Session/JWT — secrets ב-.env, לא בקוד.

פרויקט Capstone — TaskFlow

TaskFlow: login בסיסי + protected routes.

מושגי מפתח

רחפו מעל שם המושג (או לחצו במסך מגע) לפירוט: מבוא, משמעות וכוונה.

Authentication

מבוא

לפני מה מותר צריך לדעת מי אתה. Authentication היא הזיהוי.

משמעות

תהליך login שמוכיח זהות: סיסמה חזקה, hashing, לא סיסמה בטקסט גלוי.

כוונה

הכוונה: לזהות משתמש בשרת, לא רק להסתיר כפתור ב-Frontend.

מי אתה.

דוגמה: login
זהירות: plain password.

Authorization

מבוא

משתמש מחובר עדיין לא רשאי לכל דבר. Authorization היא ההרשאה.

משמעות

כללים: אילו משימות רואים, אילו פעולות מותרות. מונע גישה ל-ID של אחר.

כוונה

הכוונה: לבדוק בעלות בשרת בכל /tasks/:id — זה מניעת IDOR.

מה מותר.

דוגמה: my tasks only
זהירות: IDOR.

Session/JWT

מבוא

אחרי login צריך הוכחה לכל בקשה. Session או JWT הם ההוכחה.

משמעות

אמצעי לזהות בקשות עוקבות. Cookie עם httpOnly עדיף על JWT ב-localStorage.

כוונה

הכוונה: לא לחשוף טוקן ל-JavaScript אם אפשר — XSS גונב localStorage בקלות.

proof after login.

דוגמה: httpOnly cookie
זהירות: localStorage JWT — JavaScript בדפדפן יכול לקרוא localStorage, ולכן token שמור שם חשוף ל-XSS. httpOnly cookie נחסמת לגישה מ-JS — הדפדפן שולח אותה אוטומטית אבל קוד הדף לא יכול לגנוב אותה.

E2E Flow

מבוא

יחידת קוד ירוקה לא מוכיחה שמשתמש יכול להשלים תרחיש.

משמעות

מסלול מלא: login → פעולה → logout, כולל כישלון (משתמש לא מורשה).

כוונה

הכוונה: לבדוק גם את הדרך העצובה, לא רק happy path של TaskFlow.

login → action → logout.

דוגמה: create as user A
זהירות: test only happy.
משל מהעולם האמיתי

Authentication ו-Authorization הם שני בדיקות עצמאיות: מי אתה? ו-מה מותר לך?. middleware שבודק רק את ה-token אך לא את ה-ownership מאפשר IDOR — גישה למשימה של משתמש אחר דרך שינוי id ב-URL. שתי הבדיקות חייבות להיות בצד השרת.

שאלות לחשיבה: כתבו את ה-middleware של TaskFlow בשלושה שלבים: (1) פענוח token, (2) בדיקת תוקף, (3) בדיקת ownership — task.userId === req.user.id. הגדירו מה מוחזר בכל כשלון.

תרגיל עצמאי

בדקו את עצמכם

תשובה לדוגמה: identity vs permission.
IDOR?
תשובה לדוגמה: access others' data by ID — prevent server-side.
httpOnly?
תשובה לדוגמה: JS can't steal cookie.
